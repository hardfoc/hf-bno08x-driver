Detailed Description

template<typename CommType>
class BNO085< CommType >

Unified driver for the BNO08x IMU – SH-2 mode, RVC mode, and DFU.

A single template class that adapts to the transport type at compile time. The CommInterface::GetInterfaceType() method determines which mode of operation is valid:

Interface Type Valid Operations
I2C / SPI / UART Begin(), Update(), EnableSensor(), Dfu(), etc.
UARTRVC BeginRvc(), ServiceRvc(), CloseRvc()

Calling a mode-incompatible method returns false or SH2_ERR gracefully. The active mode is tracked by an internal state machine exposed via GetState(). Illegal transitions are rejected with SH2_ERR_OP_IN_PROGRESS or SH2_ERR_BAD_PARAM.

Error policy:

  • Interface/mode mismatch (e.g. SH-2 call on UARTRVC transport): SH2_ERR_BAD_PARAM
  • Runtime state mismatch (e.g. enabling SH-2 sensors while not in SH-2 state): SH2_ERR_OP_IN_PROGRESS
  • Query methods (GetState, HasNewData, GetLatest) are side-effect free with respect to last_error_.

The driver automatically re-enables configured sensors after a sensor reset (handled internally by the async event callback).

Template Parameters
CommTypePlatform-specific transport. Must inherit from bno08x::CommInterface<CommType>.
Note
The CommType instance passed to the constructor must outlive this object. The driver stores a reference, not a copy.
This class is not thread-safe. Callers must serialize access externally if used from multiple tasks/threads.
One SH-2 session per process: the CEVA SH-2 library keeps global state, so a second object's Begin() is refused with BNO08X_ERR_SH2_SESSION_IN_USE while another object's session is open. UART-RVC objects are not limited.

Initialise the sensor in SH-2 mode.

Opens the communication bus, connects to the SH-2 layer, sends the reinitialize command, and registers the internal sensor/event callbacks.

Only one BNO085 object in the process can hold an SH-2 session at a time (the CEVA library keeps a single global session). While another object holds it, Begin() returns false with BNO08X_ERR_SH2_SESSION_IN_USE and touches neither the library nor the bus. Close() or destroying the owner frees the session. UART-RVC and DFU do not use the library.

Precondition
Interface type must NOT be UARTRVC.
Returns
true on success, false on failure or wrong interface type.

◆ Dfu()

template<typename CommType >
int BNO085< CommType >::Dfu ( const HcBin_t &  fw)
noexcept

Perform a Device Firmware Update (DFU).

Execute DFU with default validation options.

The sensor must already be in bootloader mode (hold BOOTN LOW during reset). The method validates the firmware image, then transfers it in packets with CRC-16 and ACK/NAK retry logic.

Over I2C the bootloader answers at 0x28 / 0x29 (datasheet section 1.4). When the port has the optional GetI2cAddress() / SetI2cAddress() hooks, the driver switches it to BootloaderI2cAddress() of its current address for the transfer and restores the address afterwards, on every path (SH2_ERR_IO if a switch fails, SH2_ERR_BAD_PARAM if the current address is not a BNO08x address).

The image is checked before the driver touches the bus or an active SH-2 session: SH2_ERR_BAD_PARAM (and nothing sent, the session left running) for the compiled-in placeholder firmware or a copy of it, an HcBin_t with a missing function, an image shorter than 1024 bytes (an empty one included), a wrong FW-Format or an unknown part number.

Precondition
Interface type must NOT be UARTRVC.
Parameters
[in]fwFirmware image. Required: there is no default. Use MemoryFirmware (or DfuFromMemory()) for an image in memory.
Returns
SH2_OK (0) on success, or a negative SH-2 error code.
See also
MemoryFirmware For loading firmware from memory at runtime.

◆ HardwareReset()

template<typename CommType >
bool BNO085< CommType >::HardwareReset ( uint32_t  lowMs = 2)
noexcept

Perform a hardware reset via the RSTN pin.

Assert RSTN for lowMs, then release and wait for boot.

Drives RSTN LOW for lowMs milliseconds, then releases it HIGH and waits RESET_STARTUP_MS (94 ms) for the sensor to boot: t1 (internal initialization, min 90 ms) plus t2 (internal configuration, typ 4 ms) of datasheet 1000-3927 section 6.5.3, figure 6-8.

Parameters
[in]lowMsDuration to hold RSTN LOW (default 2 ms; the datasheet minimum t_nrst is 10 ns).
Returns
false if the port's GpioSet() reported an error on RSTN.

After NRST rises the hub needs t1 (internal initialization, min 90 ms) plus t2 (internal configuration, typ 4 ms) before it asserts H_INTN and can be addressed (datasheet 1000-3927 section 6.5.3, figures 6-8 and 6-9). The driver waits RESET_STARTUP_MS = t1 + t2.

If asserting RSTN fails nothing else is done. If releasing it fails the hub may still be held in reset, so the start-up wait is skipped.

◆ ServiceRvc()

template<typename CommType >
void BNO085< CommType >::ServiceRvc ( )
noexcept

Poll for RVC frames and dispatch callbacks.

Read all available UART bytes and parse RVC frames.

Reads all available UART bytes, feeds them into the frame parser, and invokes the RVC callback for each complete valid frame. Call this in your main loop or an RTOS task.

Note
No-op if BeginRvc() has not been called.

Each byte is fed into a 19-byte sliding window. When a valid frame is detected (0xAA 0xAA header + matching checksum), the fields are extracted, decoded to floating-point, and dispatched to the RVC callback.
