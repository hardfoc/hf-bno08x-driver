Detailed Description

Portable framing for SHTP over UART (UART-SHTP mode, PS1 = 1, PS0 = 0).

In UART-SHTP mode every SHTP transfer travels inside a frame (datasheet 1000-3927 section 1.2.3.1, which defers to the SHTP reference manual 1000-3535; byte values as in CEVA's reference UART HAL):

Byte(s) Value
0 Flag 0x7E
1 Protocol ID: 0x01 SHTP transfer, 0x00 control
2 .. n-2 Payload; 0x7E / 0x7D sent as 0x7D, byte XOR 0x20
n-1 Flag 0x7E

Before sending a frame the host asks how much the hub can accept with a Buffer Status Query (control frame with no payload: 7E 00 7E); the hub answers with a control frame carrying the free space as a 16-bit little- endian count. The host sends a frame only when it fits, one byte at a time with at least HOST_BYTE_GAP_US between bytes (section 1.2.3.1). Bytes from the hub have no spacing.

This header has no platform dependencies: a UART port encodes with EncodeFrame() and feeds every received byte to FrameDecoder::Push(). The ESP32 reference port is examples/esp32/main/esp32_bno08x_uart_bus.hpp.
